# Как устроен тренажёр и как его менять

Код (`app.js`, `styles.css`, `index.html`, `sw.js`) — это основа. Всё, что меняется регулярно, лежит в `data/` в виде JSON. Почти любое обновление — это правка или добавление одного JSON-файла плюс новая версия в `data/manifest.json`.

## Карта файлов

| Файл | Что в нём | Когда менять |
| --- | --- | --- |
| `data/manifest.json` | версия и список всех файлов данных | при каждом обновлении: поднять `version`, добавить новый набор в `packs` |
| `data/topics.json` | все темы программы: id, название, стиль; `planned: true` — тема без вопросов, в «Прогрессе» показывается «уточняется» | новая тема |
| `data/bank/*.json` | наборы вопросов | новые вопросы, правки |
| `data/weeks.json` | план недель: цель, минимум/максимум, самопроверка, `focus` — темы недели (блоки вопросов на главной), `links` — источники недели | новая неделя, правки плана, распределение вопросов по неделям |
| `data/config.json` | размер раунда, новых в день, интервалы повторений, XP, уровни | настройки |
| `data/changelog.json` | список изменений для экрана «Что нового» | при каждом обновлении |
| `tools/validate.py` | проверка данных | запускать перед каждой публикацией |

## Код доступа

`data/config.json → pin: {salt, hash}`. Код спрашивается один раз на устройстве, потом устройство запоминается. Хранится только `hash = sha256(salt + ":" + код)`, сам код в файлах не лежит. Сменить код: новый `salt` (случайная строка) и новый `hash`; после этого каждое устройство спросит новый код один раз. Убрать код: удалить поле `pin`.

```python
import hashlib, secrets; salt = secrets.token_hex(8); print(salt, hashlib.sha256((salt + ':' + '1234').encode()).hexdigest())
```

## Темы недели (`weeks.json → focus`)

Главная показывает только блоки текущей недели: `{"id": "w1-sql", "name": "Теория SQL", "style": "pink", "ids": [...]}`. Новые вопросы «Раунда дня» берутся только из блоков недели, повторы — из всего банка. Каждый новый вопрос нужно положить в блок какой-то недели (валидатор предупредит о нераспределённых). Ориентир — 40–60 вопросов в неделю. Источники недели: `links: [{"title", "url", "note"}]`; в `note` указывать, нужен ли VPN.

Согласовано с Анисьей: Excel — «Планета Excel» (YouTube и planetaexcel.ru), SQL — LeetCode Top SQL 50, Power BI — плейлист iTempUniversity «Курс Power BI». Статистика — пока только текст, без видеолекций. Продуктовые лекции — только те, что пришлёт Анисья.

## Версия

`manifest.version` — строка `ГГГГ-ММ-ДД.N`. При любом изменении поднять её и добавить запись в начало `changelog.json` с той же версией. Если менялись `app.js`, `styles.css` или `index.html`, поменять ещё и `CACHE` в `sw.js` (например, `trainer-v3` → `trainer-v4`).

## Наборы вопросов (`data/bank/*.json`)

```json
{ "pack": "interview-ozon-2026-12", "title": "Собеседование Ozon, декабрь 2026", "added": "2026-12-05", "questions": [ … ] }
```

Именование наборов: `<тема>-base` — базовые; `articles-ГГГГ-ММ` — кейсы из статей за месяц; `interview-<компания>-ГГГГ-ММ` — вопросы из собеседований; `weak-ГГГГ-ММ-ДД` — добор по слабым местам из отчёта; `fix-…` не нужен: исправления вносятся в исходный набор с тем же `id`.

### Общие поля вопроса

| Поле | Обязательно | Смысл |
| --- | --- | --- |
| `id` | да | уникален во всех наборах; латиница, цифры, дефис. **Никогда не менять** у существующего вопроса: к нему привязан прогресс |
| `topic` | да | id из `topics.json` |
| `type` | да | `input`, `order`, `find`, `pick` |
| `t` | да | короткое название для списков и отчёта: «ROMI — формула» |
| `q` | да | текст вопроса |
| `tags` | нет | подборки на главной: `["Собеседование Ozon"]` |
| `table` | нет | мини-таблица как в Excel: `{"cols": ["A", "B", "C"], "labels": ["Город", "Канал", "Выручка"], "rows": [["Москва", …]]}` — буквы столбцов, подписи в строке 1, данные со строки 2 |
| `case`, `story`, `src` | нет | кейс над вопросом: заголовок, пересказ 4–6 предложений, `{"title", "url"}` |

### Типы

- **input** — ввод ответа. `check: "self"` (самооценка: Верно / Частично / Не вспомнила) или `"auto"` (сверка со списком `accept`; регистр, пробелы, кавычки, `$`, `,` / `;` / `.` не важны). `a` — эталон. `blocks` — по желанию: блоки для подсказки «собрать из блоков» в правильном порядке.
- **order** — расставь по порядку. `items` — в правильном порядке (приложение перемешает). `a` — пояснение по желанию.
- **find** — найди ошибку. `code` — массив строк, строка — массив элементов, на которые можно нажать. `err` — `[[номер строки, номер элемента], …]` с нуля; можно несколько допустимых. `a` — разбор: что не так и как исправить.
- **pick** — какой вариант неправильный. `options` — 2–4 варианта, `wrong` — индекс неправильного с нуля, `plain: true` — варианты текстом, а не кодом. `a` — разбор.

Новый формат вопроса добавляется в `app.js` в объект `TYPES` (функции `render` и `act`) и описывается здесь. Пока формат не добавлен в код, вопросы с ним просто пропускаются.

## Правила содержания (от Анисьи)

1. **Один вопрос — одно действие.** Без «и»: «Напиши формулу ROMI» и «Посчитай ROMI» — два вопроса.
2. Тренировать воспроизведение, а не узнавание: основной формат — ввод ответа. Блоки — только подсказка после ошибки.
3. Где можно не писать, не заставлять писать: порядок — через `order`, поиск ошибки — нажатием на элемент.
4. Эталон отвечает только на свой вопрос. Формула, расчёт и применение — разные карточки по шаблону «формула → пример с цифрами → где применяется».
5. В вопросах по Excel всегда давать мини-таблицу, если формула ссылается на ячейки.
6. Числа с неразрывными пробелами (`tools/validate.py --fix`).
7. Тон нейтральный и деловой, без клише и без похвалы.
8. Кейсы из статей — только пересказ своими словами и ссылка на источник, без копирования текста. Если в статье цифры условные, сказать об этом в пересказе.
9. Олист-специфика: покупатель — `customer_unique_id`, а не `customer_id`.

## Отчёт из приложения

Во вкладке «Прогресс» кнопка «Отчёт для Claude» собирает текст: точность по темам, до 20 слабых вопросов с `id` и счётчиками, заметки к вопросам (кнопка ⚑ в раунде), статус недели. По нему:

- слабые вопросы → добавить соседние вопросы на ту же тему (другие числа, другой ракурс) в набор `weak-ГГГГ-ММ-ДД`, поставить им тег, например `"Слабые места"`;
- заметки → исправить формулировку или эталон в исходном наборе, не меняя `id`;
- тема с низкой точностью → больше задач по ней в плане следующей недели.

## Документы от Анисьи (вакансии, вопросы с собеседований, конспекты)

1. Выписать темы и вопросы из документа.
2. Сверить с банком по `t` и `q`: что уже есть, чего нет.
3. Показать Анисье список «добавлю / уже есть / не по профилю» и спросить подтверждение.
4. Новые вопросы — в набор `interview-<компания>-ГГГГ-ММ` с тегом компании.
5. Если документ меняет приоритеты — поправить ближайшие недели в `weeks.json`.

## Публикация

1. `python3 tools/validate.py --fix` → должно быть `OK`.
2. Поднять версию в `manifest.json`, добавить запись в `changelog.json`.
3. Обновить файлы в GitHub (или выдать архив / изменённые файлы Анисье), обновить превью-артефакт «Тренажёр аналитика».
4. Приложение подтянет изменения при следующем открытии с интернетом; прогресс сохранится.
